# Initializers

**Статус: согласованный дизайн; модуль ещё не реализован.** Классы и сигнатуры ниже описывают будущий API.

Модуль строит начальное приближение смеси по одномерной выборке и заданному составу компонент. Пользователь
задаёт семейства, параметризации и при необходимости фиксированные параметры. Инициализатор определяет
свободные параметры и веса, возвращая `MixtureModel`, которую можно передать существующему оценщику.
Начальные значения свободных параметров пользователь не передаёт.

## Состав и порядок работы

`Initializer` объединяет три заменяемые части: разбиение выборки, оценку параметров компонент и определение весов.
Порядок работы фиксирован; произвольной последовательности шагов, как в итерационном конвейере, здесь нет.

1. Проверить выборку и задания компонент.
2. Передать выборку и упорядоченные описания компонент в `Partitioner`; получить и проверить матрицу `H`.
3. Для каждой компоненты передать выборку, её столбец `H` и описание выбранному `ComponentEstimator`.
4. Передать `H` в `WeightEstimator` и получить начальные веса.
5. Собрать `MixtureModel` и проверить допустимость начального приближения на исходной выборке.

Разбиение не выбирает способ оценки параметров, а оценка одной компоненты не требует готовой смеси.
Это позволяет менять методы независимо и выбирать разные способы оценки для компонент разнородной смеси.

В сигнатурах используются существующие типы из `pysatl_mpest.typings`: `UnivariateFloatArray` для одномерных
массивов и `MultivariateFloatArray` для матрицы принадлежностей. Тип элементов — `numpy.float64`.

## Описания компонент

### ComponentSpec

Описывает компоненту без значений свободных параметров.

| Поле | Тип | Назначение |
|---|---|---|
| `family` | `ParametricFamily` | Семейство ядра или частичное представление через `view(...)` |
| `parametrization_name` | `str` | Имя параметризации, доступной в переданном семействе |

Фиксированные параметры хранятся в частичном семействе; отдельного словаря фиксации нет. Например,
для нормальной компоненты с известным средним можно передать `normal.view(mu=0.0)` и имя `meanStd`.
Если `view` создан в другой параметризации, имя должно соответствовать именно ей. Существование
параметризации проверяется через API ядра.

Расчёт свободных параметров учитывает фиксацию: при известном среднем нормальной компоненты масштаб
оценивается относительно этого среднего. Вычислить обычные оценки, а затем подставить фиксированные значения
недостаточно. Распределение создаётся через переданное семейство с проверкой ограничений ядра.

Полностью фиксированные компоненты пока не входят в контракт: ядро запрещает фиксировать все параметры
через `view(...)`. Их поддержка требует отдельного решения. Готовое распределение само по себе не означает,
что его параметры будут зафиксированы при дальнейшем оценивании.

### ComponentInitialization

Объединяет описание одной компоненты и способ получения её параметров.

| Поле | Тип | Назначение |
|---|---|---|
| `spec` | `ComponentSpec` | Семейство, параметризация и фиксация |
| `estimator` | `ComponentEstimator` | Способ оценки свободных параметров |

В `initialize` передаётся непустая `Sequence[ComponentInitialization]`. Длина определяет число компонент,
а порядок — соответствие столбцам `H`. Отдельный класс коллекции не нужен. Один объект оценщика можно
использовать в нескольких заданиях, если он не переносит состояние компоненты или вызова между оценками.

## Инициализатор и заменяемые части

### Initializer

Конкретный класс с зависимостями `partitioner: Partitioner` и `weight_estimator: WeightEstimator`.
Задания компонент передаются при вызове, чтобы описание и способ оценки находились вместе.

```text
initialize(X: UnivariateFloatArray,
           components: Sequence[ComponentInitialization],
           *, random_state: int | np.random.Generator | None = None) -> MixtureModel
```

Один вызов возвращает проверенную смесь либо завершается явной ошибкой. Инициализатор не меняет состав
компонент, не запускает оценщик смеси, не выполняет скрытых повторов или переключений метода.

### Partitioner

Абстракция разбиения данных на заданное число компонент.

```text
partition(X: UnivariateFloatArray,
          specs: Sequence[ComponentSpec],
          *, rng: np.random.Generator) -> MultivariateFloatArray
```

Возвращает `H` размера `(n_observations, n_components)`. Жёсткое разбиение использует нули и единицы,
мягкое — вероятности. Значения конечны и неотрицательны; сумма каждой строки равна единице с численным допуском.
Нулевой столбец допустим как результат разбиения, но оценщик компоненты должен явно обработать отсутствие данных.

`H[:, j]` относится к `components[j].spec` и обрабатывается `components[j].estimator`. Если кластеризатор
переставляет метки, `Partitioner` должен восстановить соответствие. Для разнородных семейств и фиксаций
способ сопоставления является частью контракта конкретного разбиения; универсальное правило сортировки
кластеров по среднему не устанавливается.

Описания передаются разбиению, поскольку семейства и фиксация могут влиять на назначение наблюдений.
Стратегии оценки параметров разбиению не передаются.

### ComponentEstimator

Абстракция оценки параметров одной компоненты.

```text
estimate(X: UnivariateFloatArray,
         membership: UnivariateFloatArray,
         spec: ComponentSpec,
         *, rng: np.random.Generator) -> ParametricFamilyDistribution
```

Получает исходную выборку, столбец `H` и описание компоненты. Возвращает распределение ядра с заданными
семейством, параметризацией и фиксированными параметрами. Вес компоненты здесь не определяется.

Оценщик явно сообщает о неподдерживаемой параметризации или фиксации, отсутствии данных, вырождении
либо невозможности получить допустимые параметры. Старого значения для сохранения при неудаче здесь нет.
Численный метод, которому нужна собственная начальная точка, должен определять способ её получения;
интерфейс не требует случайной фиктивной компоненты.

Стратегии M-шага из `estimators` связаны с готовой компонентой и состоянием конвейера. Их предварительный
рефакторинг не требуется. Допускается локальное дублирование аналитических формул; общий код выделяется
после подтверждения общего вычислительного контракта двух модулей.

### WeightEstimator

Абстракция получения начальных весов смеси.

```text
estimate(H: MultivariateFloatArray,
         *, rng: np.random.Generator) -> UnivariateFloatArray
```

Возвращает вектор длины `n_components`. Веса конечны и неотрицательны, сумма равна единице с численным допуском.
Нулевые веса допускаются, как и в существующем `MixtureModel`.

Стандартный `MembershipWeightEstimator` нормирует суммы столбцов на общую сумму `H`. Для жёсткого разбиения
это доли наблюдений в сегментах, для мягкого — доли суммарной принадлежности. Другой способ, например равные
веса, подключается через тот же контракт.

## Случайность и повторные вызовы

`random_state` передаётся в метод `initialize`, как в существующем `MixtureModel.generate`:

- Целое число задаёт воспроизводимый запуск при одинаковых данных, конфигурации и окружении.
- Переданный `np.random.Generator` используется с продвижением его состояния.
- `None` означает отсутствие заданного seed.

Инициализатор получает один генератор через `np.random.default_rng(random_state)` и последовательно передаёт
его частям через `rng`. Стратегии не переустанавливают seed. Детерминированные реализации принимают `rng`
для соблюдения интерфейса, но не используют его. Стратегии не переносят результаты или состояние отдельного
запуска в следующий вызов.

## Валидация и ошибки

До разбиения проверяются непустая конечная одномерная выборка, непустой список заданий и доступность
параметризаций. После каждого этапа проверяется его контракт: форма и значения `H`, соответствие компонент
описаниям, размер и допустимость весов.

На выходе состав, порядок и фиксация сохранены, а логарифм плотности смеси конечен на каждом наблюдении
исходной выборки. Каждая отдельная компонента покрывать всю выборку не обязана. Нулевая плотность всей смеси,
`NaN` или `+inf` означают неудачную инициализацию. Проверка не гарантирует качество старта или сходимость оценивания.

При ошибке должна быть доступна причина, а для ошибки отдельной компоненты — её индекс. Иерархия исключений
и точные численные допуски определяются при планировании реализации. Повторы и выбор другого метода остаются
ответственностью вызывающей процедуры.

## Фасады и требования INIT

Общий `Initializer` позволяет собирать конфигурации вручную. Фасады будут задавать согласованные способы
разбиения, оценки параметров и определения весов. Выполнение INIT-требования проверяется для такой конфигурации,
а не для произвольной комбинации стратегий. Состав и названия фасадов ещё предстоит определить; нижние классы
на UML показывают примеры реализаций заменяемых частей.

| Требование | Как соотносится с дизайном |
|---|---|
| INIT-01: явное приближение | Путь через `MixtureModel` и `fit` сохраняется; валидация ручных стартов — отдельная задача |
| INIT-02: мультистарт | Внешняя процедура использует инициализатор и оценщик; в модуль не входит |
| INIT-03: кластеризация | Разбиение возвращает `H`, параметры определяются по кластерам, веса — по принадлежностям |
| INIT-04: квантильное разбиение | `QuantilePartitioner` создаёт сегменты примерно равной численности по упорядоченной выборке |
| INIT-05: моменты по сегментам | `MomentsComponentEstimator` оценивает параметры для поддерживаемых семейств и фиксаций |
| INIT-06: случайный старт | Разбиение может создавать случайные мягкие ответственности; правило масштаба обеспечивает оценщик параметров |

Наличие абстракций не означает реализации методов или поддержки всех семейств ядра. Пустые и вырожденные
сегменты, повторяющиеся значения и выборки короче числа компонент требуют явного поведения в конкретных методах.

Выбор числа и семейств компонент, мультистарт и оценивание смеси остаются за границами модуля.
